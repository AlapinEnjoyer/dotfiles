# macOS setup

This guide describes the current Apple Silicon Mac mini configuration. It is not
a generic multi-user installer: its macOS target is `ayrton@mini` (Linux uses `ayrton@uno`).
A different account, hostname, architecture, or macOS host needs its own flake
output and matching `home.username` and `home.homeDirectory` values.

## Prerequisites

Install Determinate Nix, then clone this repository. Nix-darwin intentionally
leaves the Nix installation and daemon under Determinate's control. Git is also
needed to clone the repository; install Apple's Command Line Tools if it is not
already available.

The ordinary Git flake reference omits untracked files. The bootstrap command
below uses `path:.` to include new modules and package expressions without
staging. Review the tree for secrets first, including ignored/untracked files,
because path flakes copy them into the store. Use `.#...` once sources are tracked.

## First activation

Home Manager installs the user environment. `just` is installed by that user
environment, so do not rely on its recipes before this first activation.

```sh
nix --extra-experimental-features 'nix-command flakes' build \
  'path:.#homeConfigurations."ayrton@mini".activationPackage'
./result/activate
```

The activation installs Home Manager packages, links generated configuration,
then runs `mise install --yes`. Mise installs any missing tools from the
generated global configuration. This may download external binaries and needs a
network connection on the first activation.

Next activate the system configuration and the declared Homebrew casks:

```sh
nix build '.#darwinConfigurations."ayrton@mini".system'
sudo ./result/sw/bin/darwin-rebuild switch --flake '.#ayrton@mini'
```

Keep the terminal open for the first nix-darwin activation. Read the `/etc`
backup procedure in the main [README](../README.md#first-nix-darwin-activation)
before replacing existing shell startup files.

## Ownership

| Owner | Managed state | Update behavior |
| --- | --- | --- |
| Home Manager | Shell, terminal packages, Git settings, Ghostty, fonts, mise and OpenCode configuration | `just switch-hm` |
| nix-darwin | macOS settings and nix-homebrew lifecycle | `just switch-darwin` |
| Homebrew | The casks declared in `hosts/mini/configuration.nix` | `just switch-darwin` reconciles undeclared formulas or casks with `cleanup = "zap"`, including Homebrew-defined cask data |
| mise | OpenCode, uv, Node, pnpm, Rust, and Mini-only Metal llama.cpp, all at `latest` | Home Manager installs missing tools outside dry runs; `mise upgrade` upgrades them later |
| Nix packages | OpenTofu, Terragrunt, gh, ffmpeg, Neovim, and mise itself | Update pinned inputs |
| Legacy imperative tools | `hf`, `trv`, and Cargo-installed `rustlings` | Not reproduced by this flake; reconcile individually, preferring Nix or mise |

Home Manager uses `programs.opencode.package = pkgs.emptyDirectory` to work around
a warning bug with `package = null` in the pinned Home Manager release. This
installs no OpenCode binary; mise owns OpenCode and uv at `latest`. OpenCode
self-updates are disabled so `mise upgrade` owns updates.

Semble's MCP and CLI fallback directly run
`uvx --from 'semble[mcp]==0.5.6' semble`; there is no `packages/semble.nix` or Nix
launcher. Launch OpenCode from a mise-enabled Zsh so it inherits uvx on PATH.
The first run needs network access and resolves Python dependencies into uv's
cache; they are not transitively locked by Nix. Do not run `semble install`,
`uv tool install`, or `uv tool upgrade semble` for this integration. Update the
pin in the MCP config and both instruction templates in
`modules/terminal/opencode/` together. Existing standalone copies are neither
used by MCP nor deleted here. See the
[shared integration notes](../README.md#semble-and-opencode) for safe legacy
OpenCode conflict handling and remaining runtime verification.

Mise's tool declarations are generated by Home Manager, but the versions use
`latest`. `mise install` therefore reproduces the declared tool set, not the
exact versions from an earlier machine. `mise upgrade` is never run during Home
Manager activation.

Nix is the default package owner; mise is the intended alternate for selected
runtimes and the Mini's upstream Metal llama.cpp build. Homebrew casks remain explicit macOS
migration exceptions. Existing uv/Cargo tools are retained, not silently removed.

Revalidate on the Mac with `just build-hm`, `just switch-hm-dry-run`, then
`just switch-hm`. In a fresh Zsh, run `just test-zsh` and `mise doctor`; reload
Ghostty and check Shift+Enter sends a newline and Cmd+Backspace clears the input
line. Run `just build-darwin` and review the declared Homebrew casks and installed
formulas/casks before `just switch-darwin`: `cleanup = "zap"` can remove
undeclared packages and cask data, and a build does not preview those removals.

## Subsequent changes

After changing Home Manager modules, build and activate them:

```sh
just build-hm
just switch-hm
```

After changing nix-darwin or Homebrew declarations:

```sh
just build-darwin
just switch-darwin
```

Update flake inputs deliberately. Review the lock-file change, then rebuild and
activate both outputs:

```sh
just update
just build-hm
just build-darwin
just switch-hm
just switch-darwin
```

## Validation and maintenance

```sh
just test-zsh
mise doctor
brew list
home-manager generations
```

`just gc` deletes only Nix store paths not referenced by a live root. Active
system and Home Manager generations remain roots and can still be rolled back.
`just optimise` only hard-links identical store files; it does not delete paths.

This repository does not include credentials, service logins, application data,
licensed fonts, or imperatively managed uv and Cargo tools. Reproduce those
separately.
